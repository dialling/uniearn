# UniEarn 独立网页后台

这是独立站点，直接通过网址进入，不需要从微信小程序的管理员页面打开。界面来自用户指定的 [Claude 原型](https://claude.ai/artifact/DzyWCp95fq7Xdz9fUkQtG3)，保留 11 个模块和中英文切换。

## 本机启动

在仓库根目录运行 `npm run admin`，打开 `http://127.0.0.1:4173`。登录页只显示管理员账号和密码。开发验收可访问 `http://127.0.0.1:4173/?preview=1`；只有此显式预览模式会显示演示数据，预览操作不会写入小程序。

## 连接现有微信云开发

环境：`cloud1-d1g757cev03375e35`。新后台沿用 `uniearn_accounts`、`uniearn_order_state/team-test` 和 `uniearn_order_archive`，不另建订单或用户数据库。

1. 在仓库根目录执行 `npm run admin:prepare`，把当前 `orderService` 的业务引擎复制到新云函数的部署目录。每次更新订单引擎后重新执行；不能仅上传未准备的 `adminService` 目录。
2. 在同一云开发环境新建 `uniearn_admin_sessions`、`uniearn_admin_audit`、`uniearn_admin_meta` 三个集合；将数据库安全规则设为仅云函数可读写，客户端不能直接访问。保持已有业务集合的安全规则。
3. 部署 `cloudfunctions/adminService`，选择“云端安装依赖”。这是事件云函数，使用现有 `wx-server-sdk` 运行环境，不是单独的 HTTP 云托管容器。
4. 设置云函数环境变量：
   - `ADMIN_ACCOUNTS`：沿用现有管理员账号密码配置，格式 `账号:密码;账号2:密码2`，密码至少 8 位。只配置在云端，绝不放到网页或 Git。也兼容 `ADMIN_USERNAME` / `ADMIN_PASSWORD`。
   - `ADMIN_ROLES`：可选 JSON，例如 `{"ops":"ops","helper":"support"}`。未指定的有效管理员默认 `admin`。角色由服务端决定，网页不能切换权限。
   - `ADMIN_ALLOWED_ORIGINS`：逗号分隔的精确后台来源，例如 `https://uniearn-operations.tendercalf1024.chatgpt.site,http://127.0.0.1:4173`。不要填写 `*`。
5. 按 [CloudBase HTTP 访问文档](https://docs.cloudbase.net/service/access-cloud-function)，把 `/api/admin` 绑定到 `adminService`。让这个登录接口可以接收 HTTP 请求，由云函数自身校验管理员凭据；不要把现有订单函数直接开放为匿名接口。
6. 将实际完整 HTTPS 接口 URL 写到 `dist/runtime-config.js` 的 `UNIEARN_ADMIN_ENDPOINT`，然后重新发布站点。登录用户只需填写管理员账号和密码，不需要输入接口地址。这里不能写任何密钥。

会话令牌仅保存在浏览器内存，刷新页面要重新登录；退出会撤销服务端会话，修改密码会使已有会话失效。连续 5 次账号登录失败会锁定 15 分钟。审核、修改和导出均有服务端记录及幂等操作 ID。

## 已对接

- 订单、用户、跑腿申请、地址、客服工单、取消原因和测试账本数据读取；每次列表最多 5,000 条，超过会明确提示。
- 跑腿申请通过/拒绝（检查申请版本和重复学号；写回同一账户认证）。
- 客服文字回复与工单状态，写回用户的小程序客服会话。
- 争议全额测试退款或确认结算，复用现有订单引擎；没有真实转账。
- 跑腿员违规记录添加/撤销，沿用原来的 14 天规则。
- 后台备注、标签、测试订单标记，以及脱敏 CSV 导出。
- 服务端管理员/运营/客服权限及审计日志。

## 明确的功能边界

原项目仍是团队测试账本，没有真实支付或提现。网页后台不会显示转账已完成的假成功。会员积分、营销券配置、群发通知、地点编辑、规则编辑、二维码发布、图片客服回复、原始订单聊天和照片还没有对应的小程序服务接口，因此在实时模式保持只读或明确拦截，不会声称影响了小程序。地址读取来自云端账户资料，本机保存的路线不会凭空出现在网页后台。现有 `/pages/admin` 保持可用，但不是新站点的入口。

## 校验

根目录 `npm test` 包含后台鉴权、角色限制、幂等、审核并发检查及客服写回测试。网页还需通过独立登录、演示模式、所有模块、语言和移动端的浏览器检查。

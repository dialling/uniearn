# 2026-10-25 云端接单与大厅字段修复

## 已确认的原因

从现有微信云环境下载的 orderService 仍运行旧版：接单前强制校验通用 profile.name/phone；大厅请求清空 room，公共列表不包含寝室性别、房间号、外卖柜；发布时没有保留 dormGender。

## 本次最小修复

- 已审核且同意规则的跑手可以正常接单，不再重复要求补通用资料；未认证、未同意规则、暂停接单、跨校区及自己接自己的订单仍拦截。
- 优先使用服务端保存的审核手机号；缺失时使用已有账户联系方式，不伪造手机号。
- 保存发布人提交的 dormGender / recipientGender，并返回大厅需要的 dormGender、room、pickupPoint。姓名、手机号、取件码和照片仍保持原权限。
- 原云端的 analytics、促销配置、选择行程订单与归档逻辑保留。
- 源码对照见 engine.patch；review.json 记录核对哈希。12个源文件中只有 engine.js 内容不同，其他11个文件与重新下载的云端代码相同。

## 如何生效

自动部署已尝试增量更新与完整更新，微信签名接口均返回 getCloudAPISignedHeader / system error，尚未确认云端更新成功。

使用同一小程序与环境 cloud1-d1g757cev03375e35。在微信开发者工具的云开发控制台打开 orderService，用压缩包 orderService/engine.js 更新该文件并保存部署；如采用整个函数上传，使用本修复包的 orderService 目录。此包是在当前云端代码上作最小修改的版本，不是工作区包含后续钱包改动的完整版本。

更新后重新打开大厅，现存订单的房间号和外卖柜将按实际已存数据返回。旧版提交时没有保存的寝室性别无法从房间号或楼栋可靠推断；只有发布人根据原地址补录或重新发布才能恢复该字段。新发布的订单会保存选择的男寝/女寝。

后续完整部署工作区版本前，应先合并保留云端已有 analytics、促销等功能，避免覆盖并行更新。
